# 01 · 概述：1.0 解决什么

## 一句话

Fleet Kit 1.0 是一个 **可 fork 的协作模式包**：本地起一个 **Hub（任务账本）**，外面挂一层 **MCP 工具门面**，让不同宿主上的 Agent（或两个脚本进程）围着 **同一个 task_id** 发消息、回执、改状态、可审计。

它不是网页、不是 App、不是 IDE 商店插件，也不是「已认证的 A2A/MCP 平台」。

## 用户目标如何映射到 1.0

| 用户原话里的目标 | 1.0 是否覆盖 | 1.0 怎么覆盖 |
| --- | --- | --- |
| 让别人一键复制协作模式 | 是 | `clone` + `cd fleet-kit && ./demo.sh` |
| 不同 Agent 分工协作 | 部分 | 共享任务对象 + 双向消息 + 状态机；不是同进程角色扮演 |
| 跨厂商 | 部分 | 任何会 MCP 的宿主都能贴配置接入；不依赖 Muse/厂商账号登录 |
| 实时通讯 | 弱 | 写入 Hub 后，对方在「下一次工具调用 / 短轮询」可见；无进程内推送 |

## 明确不做（非目标）

- A2A v1.0.x conformance、Agent Card 验签、双通道 JWS push
- 向任意厂商 CLI 进程里强推长连接
- 沙箱、出站限制、成本熔断、Postgres/Valkey 真实接线
- 前端控制台、Slack/Cursor 专用插件商店分发

白皮书（`WHITEPAPER.md`）仍是长期蓝图；本 Kit 是蓝图里「可复制的最小协作面」的落地，不是白皮书 18 项交付物的全集。

## 成功标准（做成的样子）

陌生人（或你自己）在无模型 API Key 时：

1. `./demo.sh` 退出码 0  
2. 日志里有两个不同 `agent_id`、同一个 `task_id`、终态 `completed`  
3. 至少一条 receipt；重复回执不再产生新副作用  
4. 客户端幂等 key 重试不产生第二条业务消息  
5. 跨租户读任务得到 404  
6. `/audit/verify` 通过  
7. MCP 工具封装与 HTTP 打到同一套 Hub 表  
8. 对外口径不写「已兼容 A2A」

仓库外 MCP 宿主（如 Cursor）贴配置调通，是完整验收的加分项（见 07）。

## 和 `prototype/` 的关系

- `prototype/`：**原 Stage 0 原型，本 Kit 开发约定不动它。**  
- `fleet-kit/`：**自包含拷贝 + MCP + demo**；协议字段为 `fleet`，并补了租户挂起隔离、状态 CAS、客户端幂等等 1.0 修正。  
- 两者不要混为一谈：跑演示请进 `fleet-kit/`。
