# 06 · 「实时」含义与边界

## 1.0 的实时

定义为：

> 一方写入 Hub 成功后，另一方在 **下一次 MCP/HTTP 读取**（或演示脚本的下一次请求）能看到；延迟通常是秒级，取决于宿主多久再调工具。

**不是：**

- 对方进程内弹窗/中断  
- WebSocket/SSE 推到任意厂商 CLI  
- 保证 <100ms 的同步聊天

## 和 ClawChat 类产品的差别

ClawChat 一类依赖「各家账号接入同一宿主」时，可能出现部分账号拒登。  
Fleet Kit 路径是 **共享账本 + MCP 配置**，不经过 Muse 登录门禁；失败模式变成「配置错 / 限流 / 宿主不支持 MCP」，而不是随机拒号。

## 推送级实时（未实现）

若要做，需要至少：

1. Hub 增加事件流（SSE 或 WebSocket），按 tenant/agent 订阅  
2. MCP 侧或旁路守护进程维持长连接并唤醒宿主（很多宿主 **没有** 标准「被推送后主动说话」API）  
3. 鉴权、断线重连、背压

这是独立版本范围，不是改两行配置。

## A2A（未实现）

A2A 是 Agent↔Agent 水平协议。1.0 故意用 MCP 垂直插座降低不确定性（SDK 换代、托管端不回 task 等）。  
若坚持 A2A：钉死 SDK 版本，双进程只做 Send Message + Get Task，且 **不宣称** 白皮书 v1.0.1 全量兼容。

## 运维限制示例

接入 LightVela 等上游模型时，模型侧可能有 RPM（如 60）。那是 **模型供应商** 限制，与 Hub 消息总线无关；协作消息本身不消耗模型额度，除非你的 Agent 逻辑去调模型。
